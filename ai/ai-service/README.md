# AI Service

Python 3.12 scaffold with FastAPI HTTP on port `8000` and standard gRPC health on internal port `50051`. FastAPI starts and stops the gRPC server in its application lifecycle, including in the Compose container. Development enables gRPC reflection. No AI business logic, prediction model, or business RPC exists.

`app/api` contains HTTP health routes; `app/grpc` contains the technical gRPC server. `app/application`, `app/domain`, and `app/infrastructure` are reserved for future slices. `tests` contains the foundation tests.

`/health/live` reports a running HTTP process. `/health/ready` reports AI application startup readiness; it does not check PostgreSQL, RabbitMQ, or telemetry backends.

Use Python 3.12 with the locked dependencies. From this directory:

```sh
python -m pip install -r requirements.lock
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
python -m unittest discover -s tests -v
```

The HTTP command also starts gRPC on port `50051`. The root Compose stack builds the service from `python:3.12-slim-bookworm` and publishes only HTTP on `localhost:8000`; gRPC is available only on the Compose network. `pyproject.toml` is the human-maintained direct dependency declaration; `requirements.lock` pins the validated runtime and test environment. To regenerate it, build the AI image with reviewed `pyproject.toml` dependencies, run `python -m pip freeze` in that Python 3.12 image, omit the local `parking-ai-service @ file:///app` entry, then validate a clean environment before committing the lock.

## Arrival-availability baseline (US-AI-002)

`POST /internal/ai/arrival-availability` accepts `lotId`, `vehicleType`
(`Car` or `Motorbike`), an offset-aware `arrivalAt`,
`heldQuotaAtArrival`, and optional `snapshots`. Each snapshot contains
`lotId`, `vehicleType`, `capturedAt`, and `availableSlots` before subtracting
held reservations. Use snapshots generated by Parking/Booking aggregation;
**do not treat client-provided numbers as authoritative**. This endpoint is
internal and is not exposed through the YARP Gateway in the current sprint.

Prediction uses historical 15-minute samples from the same lot and weekday,
then the same lot/time of day, then other lots of the same vehicle type/time.
Only timestamped historical samples earlier than the requested arrival are used.
With no samples it returns the 50% baseline. Laplace smoothing prevents a
single sample implying 0% or 100%. `estimated=true`, `insufficientData`,
`sampleCount`, and `baselineSource` explicitly signal that the OJT data is
simulated, not validated real-world availability. The estimate must never
block admission or booking. An integration from Parking/Booking to this
internal endpoint and the customer UI is still required for full US-AI-002.
The baseline does not query a database, call OSRM, or calculate ETA; the caller
must provide the arrival time and historical data. The fixed UTC+7 bucketing
avoids a Windows-only dependency on the system IANA timezone database.
